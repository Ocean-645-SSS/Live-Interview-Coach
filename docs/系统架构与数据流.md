# Interview Coach 系统数据流

## 面试准备

```text
候选人知识库 + 岗位知识库 + 版本化题库
                │
                ▼
      preparation worker（可选公司情报）
                │
                ▼
 Interview + 冻结 Plan + Session + Attempt
```

`POST /api/interviews/prepared` 可同步形成可开始的计划；`POST /api/interviews/{id}/prepare` 将耗时准备交给 Worker。计划生成后按版本保存，成为本场面试的固定依据。

## 实时面试

```text
Browser ──音频──> LiveKit ──> interview-agent
                                  │
                      STT → 状态机 → 评价器
                                  │
                          追问 / 下一题
                                  │
                                 TTS
```

1. 前端为 Session 创建 Attempt，并用短期 token 加入专属 LiveKit 房间。
2. Agent 从冻结计划构建热词并逐题推进 `ASKING → LISTENING → EVALUATING`。
3. 回答仅在匹配 Session、Attempt 和当前题目的窗口中接受。
4. 原始 transcript 永久保留；术语规范化必须能由逐项纠正记录重放得到。
5. 评价决定追问或下一题，所有状态变更均记录事件并受乐观版本控制。

## 报告与能力画像

```text
Answers + Evaluations ──> Report
          │
          └─────────────> Skill evidence ──> Progress + recommendations
```

报告和能力画像是可重新生成的派生结果，答案与评价记录始终作为审计来源。Redis 故障不改变 PostgreSQL 中的历史事实。

核心正常状态为 `CREATED → PREPARING → READY → INTRODUCTION → ASKING → LISTENING → EVALUATING → FOLLOW_UP / NEXT_QUESTION → COMPLETING → COMPLETED`；受控异常出口为 `PAUSED`、`ABORTED` 和 `FAILED`。
