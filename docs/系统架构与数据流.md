# 系统架构与数据流

本文档描述 LiveRAG 项目的整体架构、核心数据流和各模块职责。当前项目包含两大业务板块：**通用语音 RAG 助手**（LiveRAG V0）和 **AI 模拟面试教练**（Interview Coach V1/V2）。

---

## 3. 通用语音 RAG 助手数据流

### 3.1 通话开始前

```text
LiveKit job 创建
  → 读取下次通话配置的 kb_id
  → 预热该知识库 engine
  → 清空上一通话 messages / rag_context / session_system_prompt
  → 读取 knowledge_overview.md（缺失时使用降级说明）
  → 读取 system_prompt_template.md
  → 读取 SOUL.md
  → 读取 history/{kb_id}/history.jsonl 最近 N 条
  → 根据 rag_tool_mode 渲染 RAG_TOOL_DESCRIPTION
  → 写入 session/session_system_prompt.md
  → VoiceAssistant 使用固定 instructions 启动
```

### 3.2 通话中

```text
用户语音
  → LiveKit STT (Volcengine BigModel)
  → messages.jsonl 追加 user
  → Silero VAD + SemanticTurnDetector 检测说话结束
  → LLM 基于固定 instructions + 当前 messages 推理
  → auto 模式下模型可调用 search_knowledge_base tool
  → RAG 工具只查询当前锁定 kb_id
  → rag_context.jsonl 写入查询事实和证据
  → LLM 输出回复
  → messages.jsonl 追加 assistant
  → TTS (DashScope realtime) 播放
```

通话中不再拼接 history、overview 或动态 system prompt。只使用固定 instructions + 当前对话 + RAG tool result。

### 3.3 挂断后

```text
通话结束
  → 读取本次 messages.jsonl
  → 读取 SOUL.md、当前 KB overview、当前 KB 最近 history
  → Context Model 压缩成本次长期 history
  → 追加到 history/{kb_id}/history.jsonl
  → 清空 messages.jsonl
  → runtime_state.json 写入结束时间
```

## 4. Interview Coach 数据流

### 4.1 面试前准备

**同步路径（`POST /api/interviews/prepared`）：**

```text
前端创建面试
  → POST /api/interviews/prepared
  → InterviewService.create_prepared_interview()
      │
      ├── ProfileService (从 RAG 检索)
      │     ├── build_candidate_profile("default" KB)
      │     │     → CandidateProfile（技能、项目、经历）
      │     └── build_job_profile(target KB)
      │           → JobProfile（公司、岗位、技能要求）
      │
      ├── InterviewPlanner (结合画像+题库)
      │     ├── 按画像技能加权选题
      │     └── 生成 InterviewPlan
      │           ├── introduction (开场白)
      │           ├── questions[] (题目列表)
      │           └── closing_message (结束语)
      │
      ├── 创建 Interview 记录 + 冻结 Plan
      └── 创建 Session（状态: READY）
```

**异步路径（`POST /api/interviews/{id}/prepare?async=true`）：**

```text
前端触发异步准备
  → POST /api/interviews/{id}/prepare?async=true
  → API: 创建 interview_preparation Job (PG: PENDING)
  → API: 入队 Redis (interview:jobs:interview_preparation)
  → API: Interview.state → PREPARING
  → 返回 {job_id, status: "PENDING"}

BackgroundWorker 消费:
  → BLPOP 获取 job_id
  → JobRepository.mark_running() (PG: RUNNING)
  → interview_preparation_task 按 stage 顺序执行:

  Stage 1: RESUME_PARSING
    → ResumeParser.parse(kb_id)
    → RAG 检索 + LLM 事实抽取
    → CandidateFacts（纯事实，无推理）

  Stage 2: CANDIDATE_PROFILE_GENERATION
    → InterviewProfileService.build_candidate_profile(CandidateFacts)
    → CandidateProfile（含推理字段：experience_level 等）

  Stage 3: JOB_PROFILE_GENERATION
    → InterviewProfileService.build_job_profile(JD evidence)
    → JobProfile

  Stage 4: COMPANY_INTELLIGENCE（可降级）
    → IntelligenceService.get_company_profile(query)
      ├── Redis Fresh Cache? → 直接返回
      ├── Cache Miss → NowcoderSpiderProvider
      │     → MCP stdio Client → Nowcoder MCP Server
      │     → Spider 抓取 → RawInterviewExperience[]
      │     → Normalizer → Extractor → Aggregator
      │     → CompanyInterviewProfile → 写 Cache
      └── Provider 失败 + Stale Cache → STALE_FALLBACK
    → 任何环节失败 → degraded=true，继续下一步

  Stage 5: PLAN_GENERATION
    → InterviewPlanner.build(
        CandidateProfile + JobProfile + CompanyInterviewProfile?
      )
    → Pydantic 校验 + 程序级质量复核
    → 持久化 InterviewPlan（含 profile snapshots）
    → Interview.state: PREPARING → READY

前端轮询:
  → GET /api/interviews/{id}/preparation
  → 返回 stage、completed_steps、degraded 等信息
```

**降级保证：** 牛客 MCP / Spider / Cache 任意环节失败 → `CompanyInterviewProfile = None` → Plan 仍基于 CandidateProfile + JobProfile + QuestionBank 正常生成。

### 4.2 实时面试（逐题循环）

```text
前端创建 Attempt → 获得 LiveKit token + room name
  → LiveKit dispatch 到 liverag-interview-agent worker

Worker 流程:
  1. 解析 job metadata (session_id, attempt_id)
  2. 构建 InterviewService + Repository + Evaluator
  3. 创建 InterviewAgentController + LiveKitInterviewAgent
  4. 连接房间 → 启动语音管线 (STT/VAD/TTS)

每道题循环:
  ┌─ ASKING ───────────────────────────────────────┐
  │  controller.start() 根据状态决定第一句话          │
  │  → TTS 播放题目 / 追问                           │
  │  → prompt_spoken() → LISTENING                  │
  │  → 打开回答窗口，启动超时计时器                     │
  ├─ LISTENING ─────────────────────────────────────┤
  │  STT 实时转写（interim 只展示，final 收集）        │
  │  用户点"提交"/超时 → submit_active_answer()      │
  │  → Orchestrator 原子写入 Answer + Event          │
  │  → 状态变为 EVALUATING                           │
  ├─ EVALUATING ────────────────────────────────────┤
  │  Evaluator 调用 LLM 按 rubric 四维评分             │
  │  技术准确性 35% + 完整性 30% + 表达 15% + 匹配 20% │
  │  → 加权分由代码计算（不信任 LLM 算术）              │
  │  → Pydantic 校验，失败自动重试一次                  │
  │  → FollowUpPolicy 规则化决策                      │
  ├─ 决策分支 ───────────────────────────────────────┤
  │  FOLLOW_UP: 生成追问 → 播放 → LISTENING (循环)     │
  │  NEXT_QUESTION: 换题 → ASKING (循环)              │
  │  FINISH: → COMPLETING                           │
  └─ COMPLETING ────────────────────────────────────┘
      → 生成 Report → REPORT_COMPLETED → COMPLETED
```

### 4.3 断线恢复

```text
断线 → 只结束 Attempt (DISCONNECTED)，不删除 Session
重连 → 创建新 Attempt → Worker 读 Session 状态
  → INTRODUCTION: 重新播放开场白
  → ASKING/LISTENING: 重新播放当前题目
  → FOLLOW_UP: 重新播放最近一次追问
  → COMPLETING: 重新播放结束语并完成报告
```

## 5. 面试状态机

共 14 个状态、14 种事件类型。完整流转见 [interview-coach-plan.md](plans/interview-coach-plan.md) 第 5 节。

```text
核心流转:
  READY → INTRODUCTION → ASKING → LISTENING → EVALUATING
                                                │
                              ┌─────────────────┼──────────────────┐
                              ▼                 ▼                  ▼
                          FOLLOW_UP        NEXT_QUESTION       COMPLETING
                              │                 │                  │
                              ▼                 ▼                  ▼
                          LISTENING          ASKING           COMPLETED

特殊流转:
  任意可恢复状态 ←→ PAUSED (暂停/恢复)
  任意非终态 → ABORTED / FAILED (终止)
```

状态机在 `state_machine.py` 中纯计算，数据库写入由 `Orchestrator` 在事务中完成，使用 `version` 字段乐观锁。

## 6. 数据库设计

### 6.1 通用 LiveRAG

使用 SQLite (`liverag.db`) + 文件系统：

```
~/.LiveRAG/
  liverag.db                        # 知识库/文档元数据 (MetadataStore)
  rag/knowledge_bases/{kb_id}/     # 每知识库独立 workspace
    sources/{document_id}/          # 原始文件
    storage/                        # LightRAG 索引
  context/{kb_id}/
    knowledge_overview.md           # 知识库概览
  history/{kb_id}/
    history.jsonl                   # 长期历史
  session/
    messages.jsonl                  # 当前通话消息
    rag_context.jsonl               # RAG 查询日志
  prompts/
    SOUL.md                         # Agent 人设
```

### 6.2 Interview Coach

使用 SQLAlchemy ORM，SQLite（开发）/ PostgreSQL（生产），Alembic 管理迁移。8 张表：

| 表名 | 用途 | 关键约束 |
|------|------|---------|
| `interviews` | 面试顶层记录 + 冻结计划 | version 乐观锁 |
| `interview_sessions` | 状态机权威快照 | FK→interviews, version |
| `interview_attempts` | LiveKit 连接记录 | room_name 唯一 |
| `interview_events` | 状态变化事件（只追加） | event_id 幂等, version 顺序 |
| `interview_answers` | 用户回答 | (session, question, attempt_no) 唯一 |
| `answer_evaluations` | LLM 评分结果 | answer_id 一对一 |
| `interview_reports` | 面试报告 | session_id 一对一 |
| `interview_background_jobs` | 后台异步任务 | (job_type, idempotency_key) 唯一, attempt≥0, max_attempts≥1 |

**`interview_background_jobs` 表结构：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String(64) PK | 主键，格式 `job_xxx` |
| `job_type` | String(64) | 任务类型：demo / resume_parse / profile_generation / interview_preparation / report_generation |
| `idempotency_key` | String(255) | 幂等键，与 job_type 组成唯一约束 |
| `status` | Enum(PENDING/QUEUED/RUNNING/COMPLETED/FAILED) | 生命周期状态 |
| `business_resource_id` | String(255) | 关联业务资源 ID（如 interview_id） |
| `payload_json` | Text | 任务输入 JSON（含 stage 进度元数据） |
| `result_json` | Text | 任务完成的结构化输出 JSON |
| `error_message` | Text | 错误信息（截断 2000 字符） |
| `attempt` | Integer | 当前重试次数（≥0） |
| `max_attempts` | Integer | 最大重试次数（≥1，默认 3） |
| `started_at` | DateTime(tz) | 开始执行时间 |
| `completed_at` | DateTime(tz) | 完成时间 |
| `created_at` | DateTime(tz) | 创建时间 |
| `updated_at` | DateTime(tz) | 更新时间（onupdate） |

索引：`(status, created_at)`、`(job_type, business_resource_id)`

## 7. 模块边界

| 模块 | 职责 | 不负责 |
|------|------|--------|
| `liverag/agent/` | LiveKit hooks、STT/LLM/TTS 装配、通用 VoiceAssistant + InterviewAgent | 面试业务逻辑 |
| `liverag/api/` | FastAPI 管理面，路由注册，异常→HTTP 转换，依赖注入（JobRepository/RedisQueue） | 业务逻辑实现 |
| `liverag/rag/` | LightRAG Core、文档解析、知识库 CRUD、检索 | 题库/评分规则存储 |
| `liverag/context/` | 通用助手的 session prompt、history、overview | 面试结构化数据 |
| `liverag/config/` | 环境变量、settings、模型配置（含 RedisSettings/WorkerSettings/InterviewIntelligenceSettings） | 业务配置 |
| `liverag/interview/` | 面试全部业务：状态机、评价、追问、报告、题库、ORM | 通用 RAG 语音逻辑 |
| `liverag/interview/jobs/` | 后台异步任务：Job CRUD、Redis 队列、Worker 循环、任务注册表 | 实时语音链路 |
| `liverag/interview/intelligence/` | 公司面经情报：MCP Client、Spider、规范化、提取、聚合、缓存、降级 | 实时语音链路 |
| `liverag/runtime/` | 路径解析、运行状态 | 业务逻辑 |
