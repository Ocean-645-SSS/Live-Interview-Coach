# 系统架构与数据流

本文描述最终运行版本中的两条产品链路：通用语音 RAG 助手和 Interview Coach。

## 1. 通用语音 RAG 助手

```text
前端请求 LiveKit token → 加入房间 → LiveKit 调度 my-agent
                                          ↓
                                 STT → LLM → TTS
                                          ↓
                              ContextManager / RAG 工具
                                          ↓
                                  RAG Core → LightRAG
```

1. 前端选择默认知识库；会话启动时 Agent 固定该 `kb_id` 和语音模型配置。
2. LiveKit 将音频交给 Agent。STT 产生最终转写后，`ContextManager` 记录用户消息。
3. 当 Agent 调用知识库工具时，RAG 客户端携带 `session_id`、轮次和 `kb_id` 请求 RAG Core。
4. RAG Core 返回命中、证据片段与指标；调用记录写入会话审计数据。
5. Agent 使用有证据的检索结果生成回答，TTS 输出音频；回答与本轮 RAG 状态被持久化。
6. 会话结束后，History Compactor 可将有长期价值的信息追加到该知识库的历史中。无 Context Model 密钥、无有效信息或模型失败时不会删除原始记录。

## 2. 知识库索引与查询

```text
文件 / 文本上传 → 管理 API → RAG Core → 解析、分块、嵌入、索引
                                             ↓
                                     文档与任务状态

查询 → 管理 API / Agent → RAG Core → 命中上下文与来源证据
```

知识库、源文件、索引与历史以 `kb_id` 隔离。文档上传是异步任务，调用方应轮询任务状态；查询无命中时应明确表现为“无证据”，而不是将模型自身知识当作库内事实。

## 3. Interview Coach

```text
候选人资料库 + 岗位资料库 + 题库
             ↓
      准备任务（可选公司情报）
             ↓
  Interview / Plan / Session / Attempt（PostgreSQL）
             ↓
LiveKit interview-agent → 逐题采集 → 评价 → 追问或下一题
             ↓
      报告、能力画像与训练建议
```

1. 创建面试时指定候选人知识库、目标岗位及面试配置；`/prepared` 可同步生成可开始的计划，`/{interview_id}/prepare` 可走异步准备。
2. 计划从版本化题库和候选人/岗位画像中选题，冻结后成为本场面试的事实依据。
3. 创建 Session 与 Attempt 后，前端加入专属 LiveKit 房间，`interview-agent` 接管实时音频。
4. Agent 仅在当前回答窗口接收与会话、连接尝试、题目一致的提交；每题经历采集、评价、追问/下一题等受状态机约束的转换。
5. 评价保存原始转写、规范化转写和逐项纠正记录。规范化文本必须可由纠正记录从原文逐项重放得到。
6. 完成后生成报告，并将可追溯的评价证据聚合成长期能力画像。

## 4. 面试状态

核心状态依次为：`CREATED → PREPARING → READY → INTRODUCTION → ASKING → LISTENING → EVALUATING → FOLLOW_UP / NEXT_QUESTION → COMPLETING → COMPLETED`。异常出口为 `PAUSED`、`ABORTED` 和 `FAILED`。所有状态推进经事件记录与乐观版本控制，重复事件或过期版本会被拒绝。

## 5. 可观测性与恢复

- 通用会话保存消息、检索命中和运行态，便于定位回答是否使用了正确知识库。
- Interview Attempt 记录 LiveKit 连接状态；断线后可创建新的 Attempt，而不会覆盖原有面试数据。
- Redis 或外部情报源不可用时，相关异步/情报能力不可用或降级；核心历史数据仍以 PostgreSQL 为准。
